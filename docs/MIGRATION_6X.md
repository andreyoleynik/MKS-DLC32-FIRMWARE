# Миграция на arduino-esp32 2.0.x (espressif32 6.12.0)

Прошивка переведена со старого ядра **arduino-esp32 1.0.6** (espressif32 3.2.0, ESP-IDF 3.x)
на **arduino-esp32 2.0.17** (espressif32 **6.12.0**, ESP-IDF **4.4.7**). Движок остался
Grbl_ESP32 v1.1; сменился только нижний SDK/тулчейн (GCC 8.4, новый WiFi/FS/драйверы).

Ветка: `feat/sdk-6x-migration`. Сборка: `cd Firmware && pio run -e mks_dlc32_v2_1`
(RAM ~32%, Flash ~70%, boot до Grbl-готовности ~1.8 c).

База ветки — слияние с форком `andreyoleynik/MKS-DLC32-FIRMWARE` (новый SDK,
WebSocket-heartbeat, coredump, backup/restore настроек, экранные правки, потоковый
листинг файлов, оптимизации памяти), поверх которого возвращены наши фишки и внесены
фиксы стабильности.

## Что важно знать про новый SDK

- **WiFi-события**: `SYSTEM_EVENT_*` → `ARDUINO_EVENT_WIFI_STA_*`. Старые enum под 2.0.x
  компилируются, но **не матчатся** — обработчик STA-событий молча умирал. Исправлено.
- **`File.name()`** теперь возвращает basename, не полный путь. Рекурсия по подпапкам SD
  (листинг, удаление) переведена на `File.path()`.
- **WebSocket**: вместо вкомпилированной `arduinoWebSockets` внешняя `links2004/WebSockets`
  + `WEBSOCKET_HAS_HEARTBEAT` (детект мёртвых сокетов).
- **WDT**: флаг `-D CONFIG_ESP_TASK_WDT_TIMEOUT_S` под precompiled IDF — **no-op**, убран.
  Реальный агрессивный 1 c-WDT НЕ добавляли намеренно — на CNC с блокирующими SD/WiFi/LVGL
  он давал бы спурьезные ребуты = **обрыв задания**.

## Фиксы стабильности (цель: работа станка не обрывается)

Найдено многоагентной охотой на баги (22 подтверждённых), исправлено 16.

**Защита задания мотиона (job-critical):**
- Попап лимита (hard/soft) строился из protocol-task при одновременном рендере LVGL →
  порча дерева LVGL → краш при срабатывании лимита во время задания. Теперь protocol-task
  ставит флаг, виджет строит LVGL-задача.
- Глобальный SD `myFile` читался protocol-task (задание) одновременно с UI/тач
  (процент / закрытие по «Стоп») → use-after-free / битый gcode. Сериализован рекурсивным
  мьютексом (короткие секции, без зависания protocol-петли).
- `InputBuffer` ring (LCD-команды): push из LVGL-задачи vs read из clientCheckTask без
  блокировки → потеря/порча символов. Добавлен spinlock.

**WiFi-стабильность:**
- Убран ложный AP-fallback (ранний выход на `WL_NO_SSID_AVAIL`), таймаут связи 20→30 c.
- `setAutoReconnect(true)` + `setSleep(false)`; убрана межзадачная гонка `WiFi.reconnect()`.
- **AP-fallback self-heal (НЕблокирующий)**: если настроен STA, но не подключены (в т.ч.
  завис в своём AP) — раз в 60 c **асинхронно** дёргаем `WiFi.begin()` (без блокирующего
  ожидания). Критично: `handle()` работает в `clientCheckTask`, который обслуживает realtime
  feed-hold/reset/`?` — блокирующий вариант заморозил бы «Стоп» во время задания (поймано ревью).
- Лог дисконнекта с reason-кодом и throttle (не флудит CNC/serial-поток при черче роутера).

**Прочее:** `readFileLine` overflow на длинных gcode-строках; gpio_isr-ошибки на boot
(трекинг привязок ISR); RemoteClient (таймаут/IP-fast-path/teardown/anti-storm);
backup/restore — `SD.end()`; убран ошибочный `/Firmware` из `.gitignore`.

## ⚠️ Что НАДО протестировать на железе

Проверка велась на **голой плате DLC32 (USB), без тачскрина и станка**, поэтому
следующее НЕ проверено вживую и требует теста на собранном станке:

| Что | Как проверить | Почему важно |
|---|---|---|
| **Срабатывание лимита во время задания** | запустить задание, тронуть концевик ($21=1) | анти-краш попапа лимита |
| **«Стоп» с тача во время SD-печати** | SD-задание → тач «Стоп» в процессе | анти-краш SD myFile (тест-файл: `doc/sd_race_test.nc`) |
| **SD-печать целиком** | прогнать реальный gcode с SD | мьютекс myFile не ломает чтение/процент |
| **Листинг подпапок SD** | положить gcode в подпапку, открыть в WebUI | фикс `File.name()`→`path()` под 2.0.x |
| **Хоминг / концевики** | `$H` при `$22=1`, проверить алярмы | gpio ISR под 2.0.x (на boot ошибок нет) |
| **Движение/джоггинг/шпиндель/probe** | джоггинг по осям, M3/M5, probe | I2S-степпер/PWM под новым ядром |
| **Тач-меню WiFi / beep / probe-индикатор** | пройтись по экранам | LVGL-задача под 2.0.x |
| **OTA по воздуху** | `pio run -e mks_dlc32_v2_1_ota -t upload` | env-IP в `ini/mks_dlc32.ini` (по умолч. 192.168.1.53) |

## ✅ Проверено на плате (USB)

Загрузка/Grbl-init (оси/шпиндель/лимиты/пробник сконфигурированы), новый SDK в рантайме
(IDF 4.4.7), serial-консоль, NVS сохраняется при прошивке, heap здоров (~129 КБ free).
WiFi: STA-коннект надёжен (0 ложных AP-fallback в окне), **ping-soak 60 c = 0% потерь**,
self-heal. Фишки вживую: UDP-маячок (пойман пакет), удалённое управление (HELLO к серверу),
«очистить сервер → маячок снова», mDNS `mks-dlc32.local`, WebUI (HTTP 200), SD-карта
(16 ГБ) монтируется и энумерируется.

Замечание: ассоциация STA на конкретном band-steered/mesh-роутере медленная (5–22 c) —
это RF-специфика роутера, не баг прошивки; плата переживает и держит связь.

## ⏳ Осталось (готовые фиксы — config-time/edge, не во время задания)

- socket use-after-free при смене WiFi-режима (`Web_Server::end()` vs `handle()`) — нужен
  тест смены режима тачем/`[ESP115]`; фикс через флаг-маршрутизацию на clientCheckTask.
- `get_sd_state` не детектит выём карты в Idle (нужен физический выём карты).
- `setTxPower` порядок (косметика, дефолт = макс).
